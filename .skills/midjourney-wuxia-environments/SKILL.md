# 东方武侠游戏场景

为东方武侠／神话游戏生成可探索、有环境叙事的纯场景画面。默认无人、无 NPC、无角色剪影；场景自身承担主体和尺度表达。

## 生成前先确认需求

- 用户没有给出明确主题或主场景时，先问这次想生成哪类东方游戏场景，可举宗门、街巷、村庄、寺庙、雪地、湖泊等例子；不要自行随机选题后直接生成。
- 用户给出明确主题后，默认以它为联想起点，跳脱联想到同一世界中合理相关的地点；例如“街道”可延伸到旅馆、酒楼、市井摊贩、刀匠铺。不要再询问要不要跳脱联想。
- 只有主题本身不明确、无法判断要生成哪类场景时才追问。用户明确要求只画指定地点、限制联想范围或直接生成时，按其要求执行；不重复询问已说明的信息。

## 工作流程

1. **提取场景。** 抓住用户给出的主题、数量和限制，以主题为联想起点，默认跳脱推导同一世界中最主要、最有辨识度且空间逻辑成立的地点；如“街道”可联想到旅馆、酒楼、摊贩和刀匠铺。关联要来自地理、生活、营生或通行功能，不扩成无关地点，也不要求每组重复主题物件。每次给 5–10 组，用户指定数量优先；不写世界观介绍、背景故事、人物经历或剧情。常规生成不读取参考资料，只有用户明确要求参考分析时才查对应文档。
2. **写画面。** 每组只抓一个明确场景主体和少量必要环境锚点。自然说清室内、室外或过渡空间，不加固定前缀。每批同时提供中文与英文提示词；场景名放代码块外，中文提示词合并在一个代码块，英文提示词合并在另一个代码块，代码块内只放提示词。提示词保留“主体 + 场景 + 镜头 + 构图 + 氛围 + 光影 + 必要限制词”；镜头、构图、氛围、光影缺一不可。尺度与视角按主题变化，近景、小空间和局部场景与中远景搭配，不默认宏大远景、平视或完整展示。
3. **检查并精简。** 逐条确认地点、物件功能、空间连接和摄影机位置合理；无法确定的设施或关系直接删掉，不猜测补全。删去不提升主体识别、构图或氛围的词与道具。

## 画面规则

- 镜头和构图要服务于场景：可用近景／中近景／中景／远景，低／高机位、仰／俯拍、贴地、侧视、斜看、窥视、门窗框景、内外对望或局部截取；可用偏心、遮挡、对角线、纵深、留白、层叠或不完整展示。每张选合适的一两项，避免整批套同一种视角。
- 光影要形成明确视觉中心：写清亮处、暗部和视线落点，可用侧光、逆光、漏光、天光、暮光、雨雾漫射或明暗切割；不必逐盏安排灯源，不让全场平均发亮。
- 东方意境落实为藏露、虚实、疏密、远近、动静、明暗和观看路径；靠空间关系建立，不靠飞檐、灯笼、桃花、仙雾等符号堆叠。环境叙事来自空间状态、时间天气、使用痕迹与自然侵蚀，不用套路道具解释剧情。
- 建筑保持简单可信。视觉层次来自前中后景、遮挡、光影、雾气和门窗框景，不靠增加楼层、楼梯、屋顶或重复结构。室内要像一个功能明确的真实房间，不扩写成建筑群。
- 陈设只留少量符合地点用途的视觉锚点。摆设提供生活感，构图建立意境，光影形成画面重点；不为丰富而堆物件。尺度由建筑、门窗、道路、桥梁、树木或地形体现，不依赖人物。
- 不机械添加 `epic`、`AAA`、`monumental`、`highly detailed` 或“游戏 CG”等标签；CG 质感通过镜头、构图、材质状态和光影表达。限制词简短且针对本图，默认排除人物、现代元素、文字和水印。

## 出稿自检

- 场景是否属于用户主题，且地点、核心物件、用途和连接关系都合理？
- 镜头、构图、氛围、光影是否明确、互相配合，并让视线落在预期主体上？
- 有不确定或多余的细节吗？删掉它们，不用故事或道具填空。
- 是否保持纯场景、无人物；同批场景的地点、尺度、镜头或光线是否有真实变化？
